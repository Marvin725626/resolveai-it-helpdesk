# 2.1 服务目录维护

管理员在「服务目录管理」维护员工申请模板。只有工作区所有者和管理员可访问；支持专员和员工仅能读取已发布服务。

## 修改现有服务

选择服务后修改名称、简介、分类、字段或状态，点击「保存修改」。服务代码创建后固定。每次保存携带当前版本；其他管理员已更新时返回冲突，保留你的输入，核对后再刷新。保存成功会立即刷新历史修订。

切换目录、新增、复制、载入历史或刷新将替换编辑内容时，页面要求明确选择保留编辑或放弃更改并继续。保存期间暂时禁用可能改变编辑上下文的操作。

## 阅读与恢复历史

历史修订展示当时的服务内容、状态、字段、必填要求和选择项，并与当前已保存版本比较。对比对象不是尚未保存的编辑；字段按标识识别增删改，排序变化单独标明。

「恢复到编辑器」只加载历史名称、简介、分类和字段；保留当前服务代码、当前版本和发布状态。它不立即写库。核对后点击「保存修改」，生成更高版本；历史记录不被覆盖。已归档服务载入以前的已发布内容后仍保持归档，重新发布需管理员显式选择。

已提交申请的名称、标签、答案和版本快照独立保存，目录修改和恢复不会改写它们。

## 复制新服务

「复制为新草稿」取当前已保存服务内容，生成未保存草稿，清空服务代码；输入新的唯一代码后点击「创建服务」。新服务拥有独立ID与v1版本，不继承原项修订，也不会自动发布。仍受20个非归档服务上限约束。

新建请求结果不确定时，保持内容不变再次提交会复用请求ID，避免重复创建。修改内容后会使用新请求ID；发生版本冲突的已有服务保存不会自动覆盖其他人的更新。

## 运行与验证

无新增数据库迁移，沿用2.0的 `f20b8c6d4192`。运行和停止方法见[运维说明](OPERATIONS.md)。真实浏览器验收脚本：`scripts/smoke-catalog-maintenance.cjs`，需要 `RESOLVEAI_ALLOW_SYNTHETIC_WRITES=1`，仅允许本地开发地址，并创建随机合成工作区。

Playwright模块和浏览器不在默认路径时，使用 `PLAYWRIGHT_MODULE` 与 `CHROMIUM_PATH`。可选 `RESOLVEAI_QA_SCREENSHOTS=1` 将QA截图保存到私有 `.local/`，不随项目上传。
