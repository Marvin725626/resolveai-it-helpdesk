# 三分钟演示与复现

先按 README 安装并启动，在 http://127.0.0.1:5174 使用预填本地演示账号登录。

## 演示步骤

1. **有依据的回答（30 秒）**：在智能诊断输入“如何安装公司批准的办公软件？”，展示 APP-001 引用与节点轨迹。说明当前使用离线规则和 SOP 摘录。
2. **工具到工单（45 秒）**：输入“VPN 连不上，提示认证超时，怎么排查？”，查看 VPN-001、模拟服务降级与自动人工工单；打开处理记录，接手、保存内部备注、等待员工反馈、继续处理、标记解决并关闭；查看自动生成的状态时间线。
3. **筛选与导出（30 秒）**：工单队列搜索 VPN，选择状态、优先级和处理时限，导出当前结果。取消过滤后可跨页查看全部工作区工单，导出不受当前页限制。
4. **运营观测（45 秒）**：打开运营看板，切换 7 / 30 天，展示每日量、分类、转人工率与 P95，展开每日数据表，下载指标 JSON；在诊断结果选择“有帮助”，展示看板反馈数量。说明当前账号 / 工作区范围以及离线耗时限制。
5. **代码与验证（30 秒）**：打开 GitHub 的架构图、关键代码与 Actions，说明隔离测试覆盖证据缺失、重复请求、工作区隔离和统计口径。

## 自动浏览器演示

该脚本需要 Playwright 和 Chromium，不作为项目运行的必需依赖。启动服务后，在项目目录执行：

```powershell
cd frontend
npm install --no-save --package-lock=false playwright
npx playwright install chromium
cd ..
node scripts/smoke-browser.cjs
```

它通过界面登录、运行两个真实诊断、保存诊断反馈、完成接手 / 备注 / 等待 / 解决 / 关闭全流程、验证看板与下载、组合筛选、空结果和 390px 布局，并更新 `docs/resolveai-*.png`。它会在本地演示数据库新增诊断与工单。请仅在开发环境运行。

可设置 `RESOLVEAI_URL`、`RESOLVEAI_EMAIL`、`RESOLVEAI_PASSWORD` 指向开发服务。自定义浏览器路径用 `CHROMIUM_PATH`，已有 Playwright 模块用 `PLAYWRIGHT_MODULE`。密码和令牌不写入脚本输出或仓库。

## 统计定义

- 日期：香港时间的日历日，包含今天；API `days` 允许 1–90，UI 预设 7 / 30 / 90。
- 请求量：窗口内当前账号所有运行记录；完成数：`status=completed`。
- 转人工率：完成诊断中 `escalate=true` 的比例。
- 证据通过率：完成诊断中 `supported=true` 的比例；只是规则门控结果，不是正确率。
- 平均与 P95：只使用非负数值耗时的完成记录，P95 为排序后的第 `ceil(0.95*N)` 个值。
- 工单分布：当前工作区全部时间的状态计数。
- CSV：当前加载列表中筛选出的最多 100 张工单，所有单元格带引号，危险公式前缀添加单引号。

真实模型、企业工具接入、PostgreSQL 与 Docker 需要另行配置和验证；截图中的服务状态是模拟数据。

## 个人通知闭环

管理员在工单处理中将工单分派给已接受邀请的支持专员；该成员登录后打开“个人通知”，可见一条未读分派提醒。点击“打开工单”后通知变为已读，关联工单展开处理记录，可直接接手处理及推进状态。转交、释放和管理员修改负责工单状态会产生后续提醒。详见[通知规则与API](NOTIFICATIONS.md)。

`scripts/smoke-notifications.cjs` 对已经启动的隔离后端 / Vite 服务执行该闭环，默认8115 / 5185；支持`RESOLVEAI_API_URL`、`RESOLVEAI_URL`、`PLAYWRIGHT_MODULE`、`CHROMIUM_PATH`及`RESOLVEAI_SCREENSHOT`。它会创建随机密码演示账号及工单，运行时应使用临时数据库；不要对主数据库执行演示脚本。截图仅含演示姓名、工单与通知，无密码或令牌。

## AI 转人工后的报障跟进

用现有工作区成员账号提交需要人工介入的问题，点击诊断结果的“跟进这张工单”，进入“我的报障”。支持人员在队列接手，使用“公开回复”追问并设为等待员工反馈；本人刷新进度后补充资料，工单恢复处理中。支持人员标记解决后，本人刷新并确认解决关闭；若仍未解决，可填写公开说明重新处理。关闭后双方公开沟通只读，内部备注仍属于支持团队。

`scripts/smoke-requester-followup.cjs` 默认连接隔离 API8197 / Web5297，使用随机密码创建两名同工作区成员，关键追问、补充和确认均通过真实浏览器UI完成。支持`RESOLVEAI_API_URL`、`RESOLVEAI_URL`、`PLAYWRIGHT_MODULE`、`CHROMIUM_PATH`和`RESOLVEAI_SCREENSHOT`。脚本会创建演示数据，只对临时数据库运行。详见[功能边界与API](REQUESTER_FOLLOWUP.md)。

## 工单私有附件

在“我的报障”选择一张本人AI转人工工单，上传PNG截图和UTF-8 TXT排查信息；支持接手人在队列展开处理记录，通过“工单附件”下载，上传LOG回传；本人刷新进度后下载回传日志，并删除不再需要的附件。两侧上传完成后可立即公开回复，使用更新后的工单版本。

`scripts/smoke-attachments.cjs` 默认连接隔离 API8198 / Web5298，用随机密码同工作区两账号验证该流程，实际浏览器下载后检查SHA-256，并检查390px无横向溢出。支持`RESOLVEAI_API_URL`、`RESOLVEAI_URL`、`PLAYWRIGHT_MODULE`、`CHROMIUM_PATH`和`RESOLVEAI_SCREENSHOT`。脚本会创建账号、工单与附件，只对临时数据库和独立`IT_ATTACHMENT_ROOT`运行，不能指向主数据。截图仅使用合成演示内容。详见[权限、格式及维护边界](PRIVATE_ATTACHMENTS.md)。


## v1.6：一次完整的解决经验闭环

1. 用隔离演示账号发起需人工处理的诊断，在“我的报障”补充文字、截图或日志。
2. 支持人员接手，在工单详情公开回复；完成排查后填写解决分类、公开摘要和步骤，提交解决记录。
3. 报障人在“我的报障”查看本轮解决内容，确认关闭并可选评分；问题仍存在时说明后重新处理。
4. 支持人员在解决记录里整理知识草稿，在“知识库”的草稿区编辑正文与关键词。
5. 管理员审核内容，可以说明驳回或发布；发布后会得到实际知识来源代码和版本。
6. 在检索测试台搜索相关关键词，确认新来源命中。未发布草稿不能作为诊断依据。

所有示例都只表示本地演示操作，不能作为真实客户数据、生产解决率或服务效果。


## v1.7：日常分诊与团队运营

1. 在工单队列设置“由我接手”、优先级或时限等筛选，以有意义的名称保存视图，刷新页面后应用它。
2. 打开未完成工单，选择新优先级，查看从原创建时间计算的新截止时间，填写原因并提交。
3. 确认队列优先级及时限标签更新，处理记录保留前后优先级与目标时间；其他相关人员可收到固定摘要提醒。
4. 在运营看板查看独立的团队运营区：当前积压、未分派、时限状态及接手人工作量。
5. 切换7/30/90天，区分解决轮次、去重工单数和评分提交窗口，导出当前选择的指标JSON。

当前积压是全时间快照，不随历史窗口切换；空评分不会伪造均分。保存视图不会自动修改或分派工单。
