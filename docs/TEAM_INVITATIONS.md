# 工作区成员邀请

## 使用方式

1. 使用工作区所有者或管理员账号登录，打开“团队管理”。
2. 输入受邀成员邮箱并创建邀请。系统显示一次性链接；请立即复制并通过可信渠道手动发送。
3. 链接有效期为 48 小时。受邀者打开 `/invite#<token>`，确认邮箱、填写姓名并设置密码。
4. 新成员固定以“支持专员”身份进入邀请所属工作区，并可以出现在工单分派列表中。
5. 管理员可以查看成员、邀请状态、到期时间，并撤销待接受邀请。

## 安全与边界

- 令牌由密码学安全随机源生成；数据库只保存 SHA-256 摘要。明文令牌仅在创建邀请的响应中出现一次。
- 邀请页从 URL 片段读取令牌后立刻清除地址栏。查找及接受均通过 POST JSON 传输令牌，令牌不放在 API 路径或查询串中。
- 匿名查找只返回有效或无效，不暴露邮箱和工作区。列表、创建和撤销由服务端角色检查，并限定当前租户。
- 接受操作会以条件更新消费令牌，并在同一数据库事务内创建账号；重放、撤销、过期、重复邮箱及竞争接受都会失败。
- 全局账号邮箱按大小写不敏感方式唯一。注册、登录与受邀账号使用一致的规范化规则。
- 管理员应把邀请链接视为 bearer 凭证，仅发给目标人员，并在发送错误时立即撤销。

本项目当前没有邮件投递服务，也不验证受邀者是否实际控制填写的邮箱。邮箱匹配只能证明填写值与邀请记录一致，不能证明邮箱所有权。链接持有者在 48 小时内可以尝试接受邀请；这不是企业身份验证、邀请邮件或生产级账号恢复方案。

## API

所有接口位于 `/api/v1/auth/invitations`。

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| GET | `/` | 所有者 / 管理员 | 返回当前工作区成员与邀请状态 |
| POST | `/` | 所有者 / 管理员 | 创建邀请；请求 `{ "email": "agent@example.com" }`，响应含一次性 `token` |
| DELETE | `/{invitation_id}` | 所有者 / 管理员 | 撤销当前工作区的待处理邀请 |
| POST | `/lookup` | 匿名，限流 | 请求 `{ "token": "..." }`，仅返回 `{ "valid": true }` |
| POST | `/accept` | 匿名，限流 | 提交令牌、邀请邮箱、姓名和密码，创建支持专员并返回登录凭证 |

Alembic revision `2d842c6f9b3a` 添加邀请表和大小写不敏感邮箱唯一索引。开发启动时 `init_db()` 也可为本地演示库创建缺失表 / 索引。

## 验证

邀请 API 的测试覆盖一次性接受、重复使用、密码登录、角色限制、令牌摘要存储、邮箱规范化、撤销、到期、跨工作区隔离和并发接受。真实浏览器验收应使用第二个独立浏览器上下文模拟受邀成员，避免覆盖管理员的本地登录状态。

仓库中的 `scripts/smoke-invitations.cjs` 可对已启动的隔离 API / Vite 地址重放管理员邀请、第二上下文接受、支持角色和分派列表检查；它支持设置 `RESOLVEAI_URL`、`RESOLVEAI_API_URL`、`PLAYWRIGHT_MODULE`、`CHROMIUM_PATH` 和截图输出路径。
