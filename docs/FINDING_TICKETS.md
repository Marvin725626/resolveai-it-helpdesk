# 查找报障与按来源分流

## 我的报障

“我的报障”提供关键词、状态及来源组合筛选。来源可选主动报障或 AI 转人工；全部来源仍只包括当前账号有权跟进的工单。

关键词搜索工单标题、编号、本人提交的问题描述或 AI 诊断时的问题文本。内部诊断上下文、内部备注和其他报障人的内容不进入此个人搜索范围。`%` 与 `_` 按普通字符搜索。

改变筛选会回到第一页；列表总数与页数来自筛选后的结果。清除筛选后可以重新查看全部个人报障。没有工单与筛选无匹配会有不同提示。查看或刷新工单仍遵守原有报障人权限。

创建报障成功后会清除筛选并打开新工单，避免新提交被旧条件隐藏。通过通知打开工单也会清除相关条件。筛选和翻页不会清空尚未提交的报障表单。

## 支持队列

工单队列增加来源条件：

| 来源 | 含义 |
| --- | --- |
| 主动报障 | 用户从“我的报障”直接提交的工单 |
| AI 转人工 | 实际 AI 运行关联的工单 |
| 历史工单 | 没有上述创建关联的既有工单 |

来源可与已有关键词、状态、优先级、接手范围及时限组合。列表、总数、导出和个人保存视图使用相同的来源条件。CSV 增加来源列，仍保留1000行导出上限及公式前缀处理。

旧保存视图继续按全部来源应用；选择具体来源后保存的新视图，在刷新后仍会恢复该条件。旧视图的创建请求重试语义保持兼容，不需要手动迁移或重建。

## API 与实现边界

- `GET /api/v1/helpdesk/my-tickets` 支持 `q`、`status`、`source=manual|ai` 与原分页参数。
- `GET /api/v1/helpdesk/ticket-queue` 及 `/export` 支持 `source=manual|ai|legacy`；省略来源表示全部。
- 个人接口保留原有中文 `source` 展示字段，并新增 `source_code`；支持队列的 `source` 使用上述代码。
- 来源根据数据库中的提交记录与诊断运行关联判断，主动报障关联优先；不通过标题文字猜测来源。
- 所有来源及关键词条件都在数据库计数和分页前应用，关联同一工单的多条运行不会产生重复列表行。

不增加外部搜索服务或改写历史工单。43项相关隔离回归、真实PostgreSQL与浏览器完整筛选流程已通过。实际验证记录见[VALIDATION.md](VALIDATION.md)，主动报障流程见[MANUAL_REQUESTS.md](MANUAL_REQUESTS.md)。
